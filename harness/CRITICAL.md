# CRITICAL —— 不可违反的约束

> 目标：≤ 60 行 / ≈1 屏。只保留当前有效、真正关键的规则。新增前先看能否合并进现有条目。

## 产品与规则

1. **评分规则以文档为唯一真源**：`掼蛋牌型量化评分方案.md`（V4.0）与 `手牌综合牌力评估方法.md`。代码与文档冲突时，先确认哪边是需求，不得静默改公式。
2. **牌理大小关系不可破坏**：4 张炸弹 > 所有普通牌型；同花顺 > 5 张炸弹；6 张炸弹 > 同花顺；……；火箭 > 10 张炸弹。
3. **普通牌型映射上限 191**，最小四炸 192，火箭固定 1000；改动需同步文档 + 单测 + README 指标说明。
4. **级牌（逢人配）语义**：单张/纯对子/纯三张/炸弹按 15 计；顺子/同花顺优先使 Sum 最大的填法；连对/钢板/三带二按替代点数计，不强制最大化。
5. 手牌张数范围 **1～27** 必须全部可算；残局（N<10）不计散牌惩罚。

## 安全与隐私

6. **API Key 绝不入库**：不写入源码、资源、测试、文档、提交信息、截图。仅 Android Keystore 本地保存。
7. 本地识别不得上传图片；只有用户主动点“联网识图”才发送到所选 Provider。
8. 禁止在仓库内硬编码任何真实密钥或私有端点。

## 工程约束

9. 构建基线：JDK 17 / Gradle 8.9 / AGP 8.7.3 / compileSdk 35 / minSdk 26。不要随意升级。
10. 提交前必须 `./gradlew testDebugUnitTest` 通过；影响 UI/识别路径时再跑 `assembleDebug`。
11. `model_training/` 与 Android 构建解耦，其依赖不得进入 APK；未验收的 `.tflite` 不得接入正式识别路径。
12. 单牌型分值/拆牌算法改动必须补对应单元测试（`app/src/test/.../scoring/`）。

## Harness 自身

13. 知识只存一份：`AGENTS.md` + `harness/` + `skills/` 为唯一真源，`CLAUDE.md` 只做引用。
14. 会话结束前更新 `harness/state.md`；架构/规则类决策追加到 `harness/DECISIONS.md`。
15. 只增不改地覆盖历史决策是禁止的：新决策要标注取代关系，旧条目由 Cleanup 归档而非删除。
16. 上下文预算：启动加载 ≤ `AGENTS.md` + `CRITICAL.md` + `state.md` + `index.md`；其余按路由按需读取。
